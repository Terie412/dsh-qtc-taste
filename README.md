# dsh-qtc-taste

个人向的 DeepSeek Harness 工具箱。**一个插件，多个功能**，每个功能在设置里各有独立页面。

| 功能 | 设置里的页面 | 作用 |
|---|---|---|
| 个性化提示词 | 个性化 | 你自己写的偏好条目，注入每一次模型请求的系统提示词 |

## 功能：个性化提示词

把你自己的偏好写进系统提示词。

- 一条总开关 + 任意条偏好条目，每条可独立启停、排序、编辑、删除
- **即时生效**：注入内容是每次装配时现读的，改完保存后下一条消息就按新内容走，不需要重启
- **原样注入**：用户文本按字面插入，`{{ }}` 不会被当作提示词变量解析，写代码片段或模板也不会导致装配失败
- 注入位置 `order: 9800`，在工具说明之后、部署人设后缀（10200）之前

存储：`<DSH_HOME>/storages/dsh-qtc-taste/taste.json`

## 架构

```
index.js                      组装：FEATURES 列表，逐个调用 register
src/host/storage.js           共享：文档读写（原子写）、路由、Connection 围栏
src/host/features/
  personalization.js          功能：系统提示词 section + 自己的路由
client.js                     每个功能一个设置页 + 共享控件
```

**加一个新功能是局部工作**：写一个 feature 模块、在 `FEATURES` 加一行、在 Client 的 `PAGES` 加一行。已有功能不需要改动，profile 里的插件数不会随功能数增长。

每个功能各自持有：

- 自己的文档（`storage.js` 提供原子写与纯读取，读取不会在装配期间改文件）
- 自己的路由（`registerFeatureRoute` 统一 `{ ok, value }` 信封；方法名互不串台，别人的方法答 404）
- 自己的贡献点

一个功能注册失败只会在日志里报错，不会让整个工具箱下线。
